# CC Switch X v0.1.0-beta.12

This release fixes old Codex sessions reporting "model provider unavailable" after X takeover, plus two Responses-path compatibility fixes.

- Fixed stranded history sessions: the settings cache is now refreshed right after importing legacy CC Switch data, so the unify flag is no longer misread as off. Takeover stops generating `cc-switch-x-official` / `cc-switch-official`: official takeover uses the built-in `openai` bucket via an `openai_base_url` redirect when unify is off, and the `custom` mirror when unify is on; aggregate routing always uses `custom`. Legacy official-bucket history migrates to the current live bucket; all startup history migrations run after crash/takeover recovery, the unify migration retries on startup with a fast path, and the first state-DB backup is kept when migrations share a same-second batch directory. Provider switches that cross buckets now show a hint, and a migration-finished event tells users to restart Codex to unlock old sessions.
- Fixed `400 invalid_encrypted_content` when replaying third-party reasoning ciphertext to OpenAI upstreams: non-OpenAI ciphertext is dropped for OpenAI targets only (summaries are kept); third-party upstreams are unaffected.
- Normalized overlong Responses item / call IDs so upstreams no longer reject the request.

Database schema, proxy protocols, and ports are unchanged. Quit CC Switch X and back up the entire `~/.cc-switch-x` directory before upgrading; restart Codex when the first-launch history migration finishes.
All installers are built by GitHub Actions with `SHA256SUMS.txt` provided. macOS builds use ad-hoc signing without notarization; Windows installers are not yet signed with a code-signing certificate.
